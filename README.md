# MAX Autoresponder

Автоответчик **от личного аккаунта** в web-версии мессенджера MAX (https://web.max.ru/).
Python + Playwright (постоянный профиль браузера) + LLM через Cloudflare Workers AI.

> ⚠️ **Дисклеймер**: это автоматизация неофициального веб-интерфейса. Она нарушает
> правила платформы — существует риск ограничения/блокировки аккаунта. Используй
> на свой страх и риск, не для спама и массовой рассылки.

## Установка

```bash
cd max-autoresponder
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
```

Если установлен Google Chrome — бот использует его (см. `channel="chrome"` в `bot.py`).
Если нет — убери эту строку, будет работать на встроенном Chromium.

## Настройка

1. Скопируй `.env.example` в `.env` и впиши ключи Cloudflare Workers AI:

   ```
   CLOUDFLARE_ACCOUNT_ID=...
   CF_AIG_TOKEN=...
   ```

   Модель настраивается в `config.yaml` (секция `llm.model`). Список моделей:
   https://developers.cloudflare.com/workers-ai/models/

2. Параметры в `config.yaml`: кому отвечать (`all` / `whitelist` / `blacklist`),
   системный промпт, кулдаун, `fallback_reply` (автоответ при недоступности LLM).

## Запуск

```bash
python bot.py
```

- **Первый запуск**: откроется окно Chrome — зайди в MAX (QR-код или код из SMS).
- Профиль сохраняется в `.browser-profile/`, дальше бот стартует уже залогиненным.
- Если список чатов свёрнут в колонку аватарок, бот сам его растягивает.

## Как бот отвечает

За один проход бот открывает **один** непрочитанный чат и отвечает на последнее
входящее сообщение. В модель уходят несколько последних реплик этого же чата.

- Ответ уходит только в тот чат, чьё имя сейчас в шапке. Если переключить диалог
  раньше, бот черновик стирает и в чужой чат ничего не отправляет.
- После своего ответа бот следит за открытым диалогом. Новое входящее там
  приходит без бейджа «непрочитано», но бот его видит и отвечает сразу,
  не дожидаясь кулдауна.
- Кулдаун (`cooldown_seconds`) действует, когда бот сам переходит к другому
  непрочитанному чату.
- Закрытый канал, сервисный чат без поля ввода и свой канал с полем «Пост»
  пропускаются: туда нельзя оставить обычное сообщение. Такой чат запоминается
  до перезапуска и повторно не открывается.
- Уже отвеченное сообщение не обрабатывается снова, пока в списке не сменится
  превью или счётчик непрочитанных.

## Калибровка селекторов

Селекторы в `dom_selectors.py` сняты с web.max.ru. Хеши `svelte-*` не используются:
они меняются между сборками. Если после обновления сайта бот перестаёт находить
чаты или сообщения:

```bash
python inspector.py dump   # залогинься, открой чат, нажми Enter
```

В `dom-dump.json` будут реальные классы элементов. Создай `selectors.local.yaml`
(он имеет приоритет и не попадает в git):

```yaml
CHAT_ITEM: "aside button.cell"
CHAT_TITLE: "h3.title .name .text"
CHAT_PREVIEW: "> span.text"
CHAT_UNREAD: ".indicators .badgeIcon"
OPEN_CHAT: "main h2.sr-only"
MESSAGE: "main .messageWrapper"
MESSAGE_TEXT: ".bubbleContent > span.text"
MESSAGE_OUT: ".message--isOut"
MESSAGE_IN: ""
INPUT: "[data-testid='composer'] [contenteditable][role='textbox']"
```

Поле ввода — редактор Lexical: атрибут `contenteditable` пустой, не `"true"`.
Бот пишет только если плейсхолдер поля — «Сообщение» или «Комментарий».

## Файлы

| Файл | Назначение |
|---|---|
| `bot.py` | основной цикл: чат → входящее → LLM → ответ |
| `llm.py` | клиент Cloudflare Workers AI |
| `dom_selectors.py` | CSS-селекторы web.max.ru |
| `selectors.local.yaml` | твои уточнённые селекторы (создаёшь сам, не в git) |
| `inspector.py` | инструмент для подбора селекторов и отладки |
| `config.yaml` | настройки |

## Известные ограничения

- Селекторы могут сломаться после обновления web.max.ru — тогда нужна калибровка.
- Playwright останавливается, когда macOS усыпляет компьютер. Для постоянной работы
  отключи сон или запускай не на засыпающей машине.
- В групповой чат бот отвечает так же, как в личный, если там есть поле «Сообщение».
- В комментарии к посту канала бот сам не заходит.
- Список уже отвеченных сообщений хранится в памяти. После рестарта бот может
  один раз ответить на последнее входящее снова.
